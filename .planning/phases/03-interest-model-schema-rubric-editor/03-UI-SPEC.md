### Primary visual anchor

- When `coldStart === true`: the **profile textarea** is the focal point. It is the first input, the largest element (160px minimum height), receives initial focus, and sits directly under the accent-ruled cold-start notice.
- Otherwise: the **topic list** is the focal point. It is the section the user returns to most (tuning weights and previewing), and dirty rows draw attention with the accent left rule. No autofocus is applied, and the dialog opens scrolled to the top so notices stay visible.

### Weight control (`WeightControl`) `[CTX D-10]`

| Property | Value |
|----------|-------|
| Slider | `<input type="range" min={-50} max={50} step={1}>`, `flex: 1`, `accent-color` = the sign color (see Color) |
| Numeric input | `<input type="number" min={-50} max={50} step={1} class="dialog-input">`, `width: 72px`, `padding: 4px 8px`, `text-align: right`, `tabular-nums` |
| Sign label | Right of the numeric input: formatted value with explicit sign `+20` / `−15` / `0` (U+2212 minus), 13px / 600, colored by sign |
| Sync | Slider and numeric input share one state value. Slider changes are always in range |
| Out of range / non-integer / empty numeric entry | Keep the typed text, show the weight validation error, disable Save. Never silently clamp |
| Default | New topics start at `+20` `[REQ INT-02]` |
| Scale hint | Below the slider, 12px `--text-muted`, three labels spaced `space-between`: `−50 bury`, `0`, `+50 boost` |
| Accessibility | Slider `aria-label="Topic weight"`; numeric input `aria-label="Topic weight value"` |

### Preview (`TopicPreviewResult`) `[CTX D-12]` `[CTX D-13]` `[CTX D-14]`

- One `Preview topic` button per row (drafts and saved topics). A click sends one request with the row's **current draft** description and weight plus `uiStore.selectedArticleId`. Nothing is persisted.
- In flight: the button label becomes "Previewing…" (disabled), and the result slot shows "Asking Jev…" (12px, `--text-muted`). Other rows' `Preview topic` buttons stay enabled.
- The result slot is `aria-live="polite"`, 13px, on a `background: var(--bg-secondary)` strip, `padding: 8px`, `border-radius: 4px`.
- **Math display (exact formula):** `noul` = returned match in [0,1]; `m = max(0, (noul − 0.5) × 2)`; `pts = m × weight`.
  - `matchPct = Math.round(noul × 100)`, `countsPct = Math.round(m × 100)`, `pts` to 1 decimal with explicit sign (U+2212 for negatives).
  - When `m > 0`: `Match {matchPct}% → counts {countsPct}% × {signedWeight} = {signedPts} pts`. `{signedPts}` is 13px / 600 in the sign color.
  - When `m === 0` (noul ≤ 0.5): `Match {matchPct}% · No match (contributes 0)`, all `--text-muted`.
- **Live recompute on weight change:** changing only the weight after a preview recomputes `pts` client-side from the stored `noul` (no new call).
- **Stale result:** if the description changes, or `selectedArticleId` changes, after a result arrives, keep the last result dimmed (`opacity: 0.5`) and append the stale line from the Copywriting Contract. No auto-refresh.
- **Failure:** shows inline in the result slot in `.dialog-error`. Never retried automatically `[CTX D-14]`.
- **Disabled conditions** (evaluated in this order; the first match supplies the reason): not configured → circuit open → no article selected → description blank → status unknown (status query failed). The disabled button carries the reason in its `title` attribute, **and** the section-level preview target line shows the same reason once (disabled buttons do not reliably show tooltips in every browser). "Description blank" is row-specific and appears only as the button `title`.

### Unsaved-changes guard `[CTX D-08]`

- Dirty = profile text differs from the last saved value, OR any topic row differs from its saved values, OR any draft row has a non-empty description.
- Close button or overlay click while dirty: the footer is replaced by an inline confirm bar (`.dialog-actions`, `justify-content: space-between`): message on the left, Keep editing / Discard changes on the right. Nothing closes until the user picks one.
- Not dirty: close immediately.

## Copywriting Contract

Straight double quotes in UI strings; `…` (U+2026) for in-progress labels; `−` (U+2212) for negative numbers; thousands separator in `2,000`.

### Negation warning `[CTX D-09]` `[REQ INT-03]`

| Element | Copy |
|---------|------|
| Warning | `⚠ This looks negated. Describe the subject positively (e.g. "about crypto") and give it a negative weight instead.` |

Trigger: debounced 400ms after the last keystroke; case-insensitive whole-word or phrase match on `not about`, `nothing about`, `anything but`, `not`, `no`, `except`, `without`, `isn't`, `aren't`, `excluding`. `role="status"`. It clears on the next debounced check that finds no match. It never blocks Save and never rewrites text.

| Description blank (client, on a Save attempt) | `Write a description before saving.` (Save disabled while blank; the message appears if the field is blurred empty after typing) |
| 26th topic (client) | `+ Add topic` disabled with `title="You have 25 topics, the maximum. Delete one to add another."`; the count reads `25 / 25` |
| Server limit rejections (400) | Shown via the save-failure copy above, with `{detail}` = the server's ProblemDetail `detail` (e.g. `A maximum of 25 topics is allowed`) |
| Preview: not configured (503) | `Preview failed: no TypeSafe API key is configured.` |
| Preview: breaker open / transient (503, 429, 5xx, timeout) | `Preview failed: Jev is unavailable right now. Try Preview topic again in a minute.` |
| Preview: rejected input (400 / 422) | `Preview failed: Jev couldn't judge this article ({detail}). Try rewording the description.` |
| Preview: other | `Preview failed: {detail}. Try Preview topic again.` |

`{detail}` = `Error.message` produced by `raiseIfBad` in `api/client.ts`.

## Interaction & State Contract

| Behavior | Contract |
|----------|----------|
| Data loading | Three queries on open: profile, topics, status (`GET /api/interest/status` → `{configured, breakerState, coldStart}`) `[CTX D-04]`. Status is fetched every time the dialog opens (no stale cache across opens) |
| Loading copy | While the profile or topics are loading, the body shows `Loading interests…` (13px, `--text-muted`) |
| After profile save / topic add / topic delete | Invalidate the status query so `coldStart` and its notice update from the server (the client never computes cold start itself) `[CTX D-05]` |
| Per-item save | Profile Save saves only the profile. Each row's Save saves only that row (POST for drafts, PUT for saved rows). Delete is a DELETE on that row only `[CTX D-08]` |
| Save button enablement | Profile Save is enabled when the text differs from the saved text. Row Save is enabled when the row is dirty AND the weight is valid AND the description is non-blank |
| In-flight saves | The saving control shows `Saving…` and is disabled; the rest of the dialog stays interactive |
| After a successful row save | The dirty rule and "Unsaved" tag disappear, and the Save button is removed. The row keeps its position (a draft becomes a saved row in place; no re-sort until the dialog reopens) |
| Keyboard | Tab order: notices (non-focusable) → textarea → Save profile → per row: [name] → description → slider → numeric → Preview topic → Save topic → Delete topic / Discard draft → + Add topic → Close. Enter in the description input does **not** submit. The global single-key shortcuts are already suppressed while focus is in an INPUT/TEXTAREA |
| Preview target changes | The preview target line reads `selectedArticleId` live. If the user changes the article with `j`/`k` while the dialog is open (focus outside inputs), the line updates and existing results go stale |
| Configured but no key at preview time | The server returns 503 → "Preview: not configured" error copy (defense in depth; the button is normally already disabled) |
