<objective>
Make the server say why a vote's effect is what it is once engagement is part of the weight. Task 1 (tracer) appends `engagementReplaced` to each vote effect and proves it over HTTP (D-11, WR-03, SC-4). Task 2 reorders `LearnedLimit.of` so a binding clamp or range outranks the engagement cap (D-10, WR-01). Task 3 appends `engagementAtCap` to the learned-topics response so the Interests line can say "at max" even when a binding limit is reported (D-15, discretion).

Purpose: the vote toast and the Interests learned line (plan 10-03) render these server values; the client never judges a limit itself.
Output: updated `FeedbackResult.TopicEffect`, `LearnedLimit`, `TopicLearned` and `ArticleFeedbackService`, with unit, WebMvc and integration tests, and WR-01 and WR-03 set to `fixed`.
</objective>
