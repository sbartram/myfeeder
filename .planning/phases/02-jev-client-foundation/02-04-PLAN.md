<objective>
Make the TypeSafe key an optional deploy-time secret (JEV-04, SC4). The chart carries it like Raindrop's token, deploy.sh passes it through with a warning when it is absent, and a key-only change rolls the pod through a checksum/secret pod-template annotation. This is proven with helm template/lint and a fake-helm dry run, with no cluster access.

Purpose: The key has to reach the pod as MYFEEDER_TYPESAFE_API_KEY (plan 02-01 binds it from there), and rotating it has to take effect without a manual restart. A Deployment only rolls when its pod template changes, and a Secret-only change does not do that on its own. This plan is independent of the Java plans, so it runs in wave 1.

Output: four edited deploy files. No deploy to k3s in this phase (RESEARCH Open Question 3: there is no user-visible feature yet, and the first keyed deploy is Phase 7).
</objective>
