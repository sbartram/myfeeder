# Phase 05 — UI Design Contract

> Visual and interaction contract for the Priority view (feed-tree entry, `/priority` list, status banner, "Not yet scored" separator, ↻ refresh with "Ranking changed" hint), the 0–100 interest badge in every list and the reading pane, and the reading-pane matched-topic chips and "Why N?" breakdown. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** new `PriorityList` (article-list panel for `/priority`), `PriorityBanner`, `InterestBadge`, `ScoreRow` (badge + chips + Why toggle) and `WhyBreakdown` components. Edits to `FeedPanel.tsx` (smart views), `ArticleList.tsx` and `BoardArticleList.tsx` (badge slot), `ReadingPane.tsx` (score row under the title), `App.tsx` (route + keyboard list source), `useKeyboardShortcuts.ts` (`g p`, `i`, Priority-only `j` paging and `r`), `ShortcutOverlay.tsx`, and new rules in `src/main/frontend/src/App.css`. The component file split is the planner's call; the names above are what the contract refers to.

**Out of scope, render nothing for these:** thumbs up/down buttons and feedback-adjusted weights (Phase 6), the ≥70 count on the Priority item (PRIO-V2-02), sort-by-interest in other lists (PRIO-V2-03), "mark all below as read" (PRIO-V2-01), low-confidence hints, "scored before topic X existed" notes, clickable chips, a failed-count in the banner, a separate "Too old to score" segment `[CTX Deferred]`.

**Source legend:** `[CTX D-nn]` = locked decision in 05-CONTEXT.md; `[CTX carry]` = "Carried forward" block in 05-CONTEXT.md; `[REQ]` = REQUIREMENTS.md PRIO-01..08 / ROADMAP.md Phase 5 criteria; `[CODE]` = detected in the existing frontend; `[P03]` = approved 03-UI-SPEC.md convention; `[DEFAULT]` = researcher default in a Claude's-Discretion area (the developer was not asked, because CONTEXT.md delegates it or the codebase already sets a convention).

## Layout Contract

### Feed-tree entry `[CTX D-12]` `[CTX D-13]` `[REQ PRIO-01]`

- Inside `.smart-views`, **first** item, above All Articles: `<div class="smart-view">` with the text `Priority`. **No icon** (All Articles and Starred have none, so the "not a star glyph" rule is satisfied by using text only) `[DEFAULT]`. **No count** `[CTX D-12]`.
- Always rendered, including when Jev is not configured `[CTX D-13]`.
- Active (`.smart-view.active`) when `useMatch('/priority')` matches. All Articles must **not** be active on `/priority` (today it is active whenever no feed/folder is selected).
- Click: `setSelectedFeed(null)`, `setSelectedFolder(null)`, `navigate('/priority')` (same pattern as `handleStarredClick`). Re-entering the route refetches from page 1 `[CTX D-08]`.
- Make the entry keyboard-reachable the same way the other smart views are (they are clickable `div`s today; do not change their semantics in this phase).

### Priority panel (`PriorityList`, route `/priority`) `[REQ PRIO-01, PRIO-02, PRIO-06]`

Top to bottom, inside `.article-list` (`background: var(--bg-tertiary)`):

1. **Toolbar** (`.article-list-toolbar`, existing 10px 12px padding, bottom border): left `<span class="toolbar-title">Priority</span>`; right the refresh button (see Refresh). **No "Mark all read" button and no split menu** `[CTX D-16]`.
2. **Status banner** (`PriorityBanner`), 0 or 1 line, directly under the toolbar `[CTX D-14]`.
3. **Filter input** (`.search-input`, unchanged).
4. **Rows** (`.article-items`, scrolls, inline font-size from `articleListFontSize`):
   - Scored segment: rows in server order (score DESC, date DESC, id DESC). Never re-sorted on the client.
   - "Not yet scored" separator (`.priority-separator`), rendered once, immediately before the **first loaded unscored row**. If the first page has no scored rows (not configured, cold start, nothing scored yet) the separator is the first thing in the list. Not rendered when no unscored row is loaded.
   - Unscored segment: rows by date DESC, including unread articles older than the 14-day window, with no extra separator `[CTX D-15]`.
   - `Load more` button (`.load-more`) while `hasNextPage` `[CTX D-10]`.
5. The list always renders below the banner, whatever the banner says `[CTX D-14]`.

## Typography

Exactly 4 sizes and 2 weights for everything this phase adds `[DEFAULT]` `[CODE]`. **The 1px-step scale (11 / 12 / 13 / 14) is intentional:** every size is already in `App.css` (11 via the `.article-item-meta` 0.85em ratio, 12 `.toolbar-btn` / `.article-meta` ratio, 13 list and notice text, 14 `.toolbar-title`), and this phase adds no new size. 11 is kept rather than merged into 12 because the list badge must sit on the same em ratio as the row's meta line so it tracks the list font-size preference; a fixed 12px would not scale. Roles are separated by context (list vs reading pane vs banner) and by weight, not by size steps:

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Meta | 11px at Medium (`0.85em` of the list font, the `.article-item-meta` ratio) | 600 | 1 | List-row badge numerals |
| Label | 12px (fixed in the list panel; `0.8em` of the reading font in the pane = the `.article-meta` ratio) | 400 (badge numerals 600) | 1.5 | Reading-pane score row (badge, chips, Why toggle); `↻ Refresh ranking` (inherited `.toolbar-btn`); "Not yet scored" separator (600) |
| Body | 13px (fixed in the banner; `0.87em` of the reading font in the breakdown) | 400 (lead phrase and total line 600) | 1.5 | Status banner; breakdown rows, total line, non-matching footer |
| Heading | 14px | 600 | 1.2 | Toolbar title `Priority` (inherited `.toolbar-title`). Existing `EmptyState` text also renders at 14px / 400 (inherited, unchanged) |

Weights: **400 (regular)** and **600 (semibold)** only. 600 is used for badge numerals, the banner lead phrase, the separator label, and the breakdown total line.

Numerals: `font-variant-numeric: tabular-nums` on badges and the breakdown so the points column aligns and "100" does not widen the pill.

| Refresh | See Layout → Refresh. Selection is kept; list scrolls to top |
| Hint | Lit by interest saves and by a drop in `eligibleUnscored` versus the value at the last page-1 load; cleared by Refresh or re-entry `[CTX D-08]` `[DEFAULT]` |
