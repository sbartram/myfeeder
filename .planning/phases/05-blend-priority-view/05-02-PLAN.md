Output: `articlesApi.priority`, `Article.interestScore` (TS), `usePriorityArticles`, `PriorityList`, `InterestBadge`, `tierOf`, `EmptyState` `detail`, the `/priority` route and CSS.
</objective>

Backend contract (plan 05-01, same wave; pinned here so both sides agree):
- `GET /api/articles/priority?limit=<n>[&before=<articleId>]` returns `{ items: Article[], nextCursor: number | null }`. Items are unread articles in ranked order (score DESC, date DESC, id DESC), then unscored ones by date. `before` names the last item of the previous page. HTTP 404 when `before` names an article that no longer exists (restart from page 1).
- Every item carries `interestScore`: an integer 0..100, or `null` when unscored.

Existing frontend facts (verified):
- `api/client.ts`: `apiGet(path)` fetches `/api${path}` and throws `ApiError` (`readonly status: number`) on a non-2xx response.
- `queryClient.ts`: global `queries: { staleTime: 30_000, retry: 1 }`; the Priority hook must override staleTime.
- `useArticles.ts` invalidates the `['articles']` prefix after state mutations; a `['priority']` key is never matched by it.
- `ArticleList.tsx` lines 100-107 hold the `formatTime` helper, lines 58-67 the title/summary filter, lines 131-186 the toolbar/search/rows/Load more markup.
- `components/InterestsDialog.test.tsx` lines 11-160 hold the fetch-stub pattern (`vi.spyOn(globalThis, 'fetch')` with a route table and recorded calls).
