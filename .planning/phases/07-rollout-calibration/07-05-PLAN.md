Use the file's style: bullets with a bold lead-in, concrete files and keys, and no secret values. Confirm each fact in the source files from read_first before writing it. Write these bullets in this order:

1. `- **App-owned client bean**:` `config/TypeSafeConfig` defines the `TypeSafeClient` bean, so the starter's `@ConditionalOnMissingBean` backs off and a blank key never crashes startup. It logs `TypeSafe Jev not configured; interest scoring disabled`. The key is read only through a Supplier and is never logged. `baseUrl` is set explicitly, with no `TYPESAFE_*` env fallback. The bean gets a Jev-only Reactor Netty request factory on a `clone()` of the auto-configured `RestClient.Builder` (connect 5s, read = `spring.ai.typesafe.timeout` 30s). Never build a second TypeSafeClient or reuse its transport for feeds.
2. `- **Single retry layer**:` `spring.ai.typesafe.retry.max-retries: 0`. The Resilience4j `jev` retry is the only retry: 3 attempts, then 1s and 2s via `TypeSafeConfig.jevRetryInterval`, and a 429's `retry-after-ms` is honored, clamped to 0..10s (`MAX_RETRY_AFTER_MS`). It retries only 429, 5xx/overloaded and connection or timeout failures, never 400/422/401/403. The `jev` breaker is the outer aspect (order 1 vs 2): COUNT_BASED window 20, minimum 10 calls, 50% failure rate, slow calls over 15s at 50%, OPEN for 60s, then automatic HALF_OPEN. 401/403 are recorded, so a bad key opens the breaker. Never re-enable SDK retries, because two layers multiply 429s.
3. `- **Jev event log lines**:` `config/JevEventLogging` (D-15) logs `Jev retry attempt N after <Exception> (waiting M ms)` (INFO), `Jev retries exhausted after N attempts: <Exception>` (WARN) and `Jev circuit breaker <FROM>_TO_<TO> (failure rate x%, slow-call rate y%)` (WARN), with class names and numbers only. Grep prod with `kubectl -n myfeeder logs deploy/myfeeder | grep 'Jev '`.
4. `- **Scoring executor**:` bean `interestScoringExecutor` (`InterestScoringConfig.EXECUTOR`, threads `jev-score-`). Core = max = `myfeeder.interest.concurrency` (1), `queue-capacity` 1000, and the default abort policy is kept on purpose: `ScoringQueue` catches `TaskRejectedException` and releases the id. `defaultCandidate = false` keeps Boot's `applicationTaskExecutor`. Inject it with `@Qualifier(InterestScoringConfig.EXECUTOR)`. There is no `@Async`.
5. `- **Sweep**:` `InterestScoringSweep` runs with `fixedDelay` = `sweep-delay` (PT2M) after `sweep-initial-delay` (PT1M). It enqueues min(queue room, `sweep-batch-size` 50) eligible articles, newest first. It skips when Jev is unconfigured, the breaker is OPEN/FORCED_OPEN, or in cold start; HALF_OPEN runs. New articles are also enqueued on ingest (`InterestScoringListener` → `ScoringQueue`), and the batch size does not cap those.
6. `- **Eligibility window**:` `read = false AND COALESCE(published_at, fetched_at) > now − window-days` (14), with no score row or a FAILED row under 3 attempts (`ArticleScoreStore.ELIGIBLE` / `NEEDS_SCORING`). Transient failures (429, 5xx, connection, open breaker, missing key, 401/403) write no row and use no attempt (`ScoringFailure.isTransient`), so a 429 never creates a FAILED row.
7. `- **Throttle levers**:` if 429s or the breaker become a problem (D-08), lower `sweep-batch-size` and/or lengthen `sweep-delay` in application.yaml. The emergency lever without a release is `kubectl -n myfeeder set env deploy/myfeeder MYFEEDER_INTEREST_SWEEPBATCHSIZE=20`, which restarts the pod. Once the value is in yaml, remove the override with `kubectl -n myfeeder set env deploy/myfeeder MYFEEDER_INTEREST_SWEEPBATCHSIZE-`, because a Helm upgrade can keep an out-of-band env var. For an emergency stop, redeploy with `MYFEEDER_TYPESAFE_API_KEY` unset. Keep `concurrency: 1` (D-07) and never add the SDK retry layer.
8. `- **Tier thresholds and tuning**:` `myfeeder.interest.blend.tiers.high|neutral` (`MyfeederProperties.Interest.Blend.Tiers` → `TierThresholds`) is served as `tiers` on `/api/interest/status`. The frontend reads it through `useInterestTiers` → `TierContext` → `InterestBadge`, with `DEFAULT_TIERS` 70/40 until status loads. Every blend constant is query-time, so changing one needs no Jev re-score. To tune, run `scripts/interest-calibration-replay.sh PP:HIGH:NEUTRAL ...` (a read-only psql replay of the verbatim `InterestScoreQueries` blend, drift-guarded by `InterestCalibrationReplaySqlTest`, needs `MYFEEDER_PG_PASSWORD` and the LAN). Record the result in `.planning/phases/07-rollout-calibration/07-CALIBRATION.md`. Put tuned values in main `application.yaml` and `src/test/resources/application-dev.yaml`, and keep the test yaml at profile-points 100 / 70 / 40, because `InterestScoreQueriesTest` fixtures assume them. Never use Helm `--set` or env overrides (D-14).
