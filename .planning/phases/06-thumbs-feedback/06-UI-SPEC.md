# Phase 06 — UI Design Contract

> Visual and interaction contract for thumbs up/down in the reading pane (buttons plus `u` / `d`), the thumbs-down topic picker ("Narrow…", Shift+D), the vote effect toast, the "No topics matched — Create topic from article" line and its prefilled draft in `InterestsDialog`, the learned part in "Why N?" rows, and the base-vs-learned display in the topic editor. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this contract:** new `FeedbackBar` (vote buttons, narrow control, no-match line) and `NarrowPicker` (popover) components; edits to `ReadingPane.tsx` (toolbar), `WhyBreakdown.tsx` (learned part), `TopicRow.tsx` (learned line), `InterestsDialog.tsx` / `TopicsSection` (prefilled draft, at-max notice, learned-load error), `useKeyboardShortcuts.ts` (`u`, `d`, Shift+D), `ShortcutOverlay.tsx`, `Toast.tsx` (one attribute, see Accessibility), and new rules in `src/main/frontend/src/App.css`. The component file split is the planner's call; the names above are what the contract refers to.

**Out of scope, render nothing for these:** a vote indicator or thumbs in list rows (D-02, Deferred), thumbs on list-row hover (Deferred), "reset learned adjustment" (FDBK-V2-01), vote counts per topic, re-judging an article after "Create topic from article" (D-21), any action button inside the toast (D-13, D-19).

**Source legend:** `[CTX D-nn]` = locked decision in 06-CONTEXT.md; `[CTX carry]` = its "Carried forward" block; `[CTX disc]` = its "Claude's Discretion" list; `[RES]` = 06-RESEARCH.md (pattern / pitfall / resolved open question); `[REQ]` = REQUIREMENTS.md FDBK-01..07 / ROADMAP.md Phase 6 criteria; `[CODE]` = detected in the existing frontend; `[P03]` / `[P05]` = approved 03-UI-SPEC.md / 05-UI-SPEC.md convention; `[DEFAULT]` = researcher default in a discretion area (not asked, because CONTEXT.md delegates it or the codebase already sets the convention).

## Layout Contract

### Reading toolbar with vote buttons `[CTX D-01]` `[CTX D-13]` `[CTX D-16]` `[REQ FDBK-01, FDBK-06]`

```
★ Star  👍 Up  👎 Down  Politics only  ● Mark Read  📋 Board  🔖 Read Later  …      ↗ Open Original
```

| Property | Value |
|----------|-------|
| Order | `★ Star`, then a `<div class="feedback-group">` holding `👍 Up`, `👎 Down` and (when shown) the narrow control, then the existing buttons unchanged |
| Group box | `.feedback-group { position: relative; display: flex; align-items: center; gap: 8px; }` (the popover anchors to it) |
| Vote buttons | `<button class="toolbar-btn vote-btn" aria-pressed="{active}" aria-label="Thumbs up" title="…">👍 Up</button>` and the same for `👎 Down` / `aria-label="Thumbs down"`. The visible label never changes with state (it's an `aria-pressed` toggle) |
| Idle state | Inherited `.toolbar-btn`: `--text-muted`, hover `--text-primary`, weight 400 |
| Active state (`aria-pressed="true"`) | `.vote-btn[aria-pressed='true'] { color: var(--accent); font-weight: 600; }`. Weight is the non-color cue; `aria-pressed` carries it to assistive tech. At most one of the two is active |
| `title` | Idle `Thumbs up (u)` / `Thumbs down (d)`; active `Remove thumbs up (u)` / `Remove thumbs down (d)` |
| Press rule | Same vote again → remove; the other vote → flip `[REQ FDBK-01]`. The pressed state updates **synchronously on press** from the client intent, before the request resolves `[RES Pattern 5]` |
| Not disabled while saving | Buttons stay enabled during a request; rapid presses are queued in order `[RES Pattern 5]` |
| Toolbar wrap | Add `flex-wrap: wrap; row-gap: 4px;` to `.reading-toolbar` so the extra controls wrap in a narrow pane instead of clipping. `↗ Open Original` keeps `margin-left: auto` |
| Side effects | None. A vote never marks read, never advances, never changes selection `[CTX D-04]` |

### Narrow control `[CTX D-13]` `[CTX D-16]` `[CTX D-17]`

A `.toolbar-btn.narrow-toggle` placed directly after `👎 Down` inside `.feedback-group`.

| Property | Value |
|----------|-------|
| Shown when | The current vote is 👎 **and** (the article has 2+ matched topics **or** the vote is narrowed). Hidden for 👍, no vote, and a non-narrowed 👎 with 0–1 matched topics |
| Matched topics | `interestBreakdown.rows` with `kind === 'TOPIC'` (the server's `hinge > 0` set), in server order `[RES Pattern 7]` `[CTX disc]` |
| Label, not narrowed | `Narrow…` |
| Label, narrowed, 1 pick | `{name} only` (e.g. `Politics only`) — together with the adjacent `👎 Down` it reads as D-16's "👎 Politics only" `[DEFAULT]` |
| Label, narrowed, 2 picks | `{name1}, {name2} only` |
| Label, narrowed, 3+ picks | `{k} of {n} topics` (n = matched topics) |
| Label, narrowed, 0 current picks | `No topics` (every pick was deleted or no longer matches; the vote moves nothing) `[RES Pitfall 7]` |
| Names in the label | Each name `max-width: 12em; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; display: inline-block; vertical-align: bottom;`; the full label goes in `title` |
| Color | Not narrowed: inherited `.toolbar-btn` muted. Narrowed: `--text-secondary`, weight 400 (it is a state readout, not a second accent) |
| ARIA | `aria-haspopup="dialog"`, `aria-expanded="{pickerOpen}"`, `aria-controls="narrow-picker"`, `aria-label="Choose topics to penalize"` when not narrowed; `aria-label="Penalizing {label}. Change topics"` when narrowed |
| Click | Opens the picker. Clicking `👎 Down` still removes the whole vote `[CTX D-16]` |
| Flip to 👍 | The control disappears and the narrowing is cleared server-side (`topicIds` omitted) `[CTX D-17]` |

**Picker keyboard and focus** `[CTX D-14]` `[RES Pattern 7]` `[RES Pitfall 5]`

| Key / event | Behavior |
|-------------|----------|
| Open | Focus moves to the first checkbox |
| `1`–`9` | Toggle option 1–9 (ignored beyond the list length) |
| Space | Toggles the focused checkbox (native) |
| Tab / Shift+Tab | Move through checkboxes, Cancel, Apply (native order) |
| Enter | Apply, when at least one is checked; otherwise nothing |
| Escape / Cancel | Close with no request |
| Click outside (`mousedown` outside `.feedback-group`) | Close with no request |
| Isolation | The popover's `onKeyDown` calls `preventDefault()` + `stopPropagation()` for `1`–`9`, Enter and Escape, so no global shortcut fires (Esc must **not** clear the article selection). Other keys land on focused checkboxes/buttons and are ignored by the global handler |
| Close on | Apply, Cancel, Esc, outside click, a different article selected, or the vote no longer being 👎 |
| Focus after close | Returns to the narrow control; if the control is gone (vote changed), to `.reading-content` |

### "Why N?" rows with the learned part `[CTX D-11]` `[RES OQ3]` `[RES Pitfall 4]`

```
Profile match (Mainly)                     +64
Rust  90% × +21.8 (+20 +1.8 learned)       +20
Politics  60% × −28.8 (−30 +1.2 learned)   −17
Go  70% × +10                               +4
───────────────────────────────────────────────
Score                                       71
```

| Property | Value |
|----------|-------|
| Learned part present | When `round(learnedWeight × 10) ≠ 0`: `{name}  {countsPct}% × {formatSigned(weight, 1)} ({formatSigned(baseWeight)} {formatSigned(learnedWeight, 1)} learned)` |
| No learned part | Otherwise print exactly today's label `{name}  {countsPct}% × {formatSigned(weight)}` (Phase 5 tests stay green) |
| Which learned value | `learnedWeight` = the **applied** part (effective − base, from SQL), so base + learned always equals the printed weight, even when the sign clamp or ±50 range cut the capped value `[RES Pitfall 4]` |
| Points column | Unchanged: server integer points; rows still sum exactly to the badge `[CTX D-11]` `[P05]` |
| Row `title` | `Match {matchPct}% → counts {countsPct}% × {weight 1dp} = {exact 1dp} pts · base {base}, learned {learned 1dp}` (the `· base …` suffix only when a learned part is present) |
| Chips | `ScoreRow` chips are unchanged (they already filter `weight !== 0`, so a sign-clamped topic at 0 drops out of the chips but stays in the Why rows) |

### Topic editor base vs learned (`TopicRow`) `[REQ FDBK-07]` `[CTX disc]` `[RES Pattern 4]`

```
[Rust        ] [The Rust programming language…                 ]
(────●──────────────)  [ 20 ]  +20                Preview topic  Delete topic
Learned from votes +4.0 · Effective weight +24.0
```

| Property | Value |
|----------|-------|
| Slider, number, sign label | Stay the **base** weight, editable exactly as today |
| Learned line | `<p class="interests-learned">` directly under the weight line (line 2), saved rows only (never on drafts). 12px, `line-height: 1.5`, label text `--text-muted`, numbers `--text-secondary`, `font-variant-numeric: tabular-nums` |
| Values | From `GET /api/interest/topics/learned` (`learned`, `effectiveWeight`, `limit`), matched by topic id. The client prints them; it never adds base + learned |
| Copy, learned ≠ 0 | `Learned from votes {formatSigned(learned, 1)} · Effective weight {formatSigned(effectiveWeight, 1)}` |
| Copy, learned rounds to 0.0 | `No learned adjustment yet · Effective weight {formatSigned(effectiveWeight)}` |
| Limit suffixes | `LEARNED_CAP` → ` (at max)` after a positive learned value, ` (at min)` after a negative one, e.g. `Learned from votes +20.0 (at max) · Effective weight +40.0`; `SIGN_CLAMP` → ` (can't cross 0)` after the effective value; `WEIGHT_RANGE` → ` (at the +50 limit)` / ` (at the −50 limit)` after the effective value |
| Unsaved base edit | While the row's weight differs from its saved weight: `Learned from votes {learned} · Effective weight updates when you save` (no client math) |
| Loading | Line absent until the learned query resolves |
| Failed | Line absent on every row; one section note under the Topics help: `Couldn't load learned adjustments. Close and reopen Interests to try again.` (13px, `--text-muted`, the `.interests-note` style) |
| Refresh | The learned query refetches after every vote and topic save/delete; row edit state is never reseeded `[RES Pattern 4]` `[P03]` |

### Effect toast `[CTX D-07..D-10]` `[CTX D-03]` `[CTX D-18]` `[REQ FDBK-04]`

Always `addToast(msg, 'success')`, text only. Numbers are the server's `after − before` per topic, printed with `formatDelta` (1 decimal, explicit sign, U+2212, rounds before signing so a tiny negative prints `+0.0`, never `−0.0`).

**List rule:** keep topics whose rounded change is non-zero **or** whose `limit` is not `NONE`; sort by absolute change DESC; show the first 3, then ` · +{N} more` when more remain.

**Entry format:** `{name} {delta}{note}`, where note is, in this order of precedence:

| Condition | Note |
|-----------|------|
| `limit = LEARNED_CAP` | ` (learned at max {formatSigned(learned)})` when learned > 0, else ` (learned at min {formatSigned(learned)})`, e.g. `Rust +0.0 (learned at max +20)` |
| `limit = SIGN_CLAMP` | ` (can't cross 0)` |
| `limit = WEIGHT_RANGE` | ` (weight at max +50)` / ` (weight at min −50)` |
| `baseWeight < 0`, no limit | ` (now {formatSigned(after, 1)})`, e.g. `Politics +1.2 (now −28.8)`, so a 👍 that softens a disliked topic reads as "still buried" `[RES OQ2]` |
| otherwise | none |

| Event | Copy |
|-------|------|
| 👍 saved (new or flipped) | `👍 Rust +2.0 · WebAssembly +1.4 · Politics +1.2 (now −28.8) · +2 more` |
| 👎 saved (new or flipped) | `👎 Rust −4.0 · Go −0.4` (a flip shows the full swing) `[CTX D-10]` |
| Vote removed | `Vote removed · Rust −2.0` `[CTX D-10]` |
| Narrowing applied or changed | `👎 Narrowed · Rust +1.8 · Go +0.4` (un-picked topics revert) |
| Narrowing cleared (all topics checked) | `👎 All matched topics · Rust −1.8 · Go −0.4` |
| Capped topic | `👍 Rust +0.0 (learned at max +20) · Go +0.2` |
| Unscored article, vote saved | `👍 Saved — counts once this article is scored` / `👎 Saved — counts once this article is scored` `[CTX D-03]` (also used for SKIPPED and exhausted-FAILED articles `[RES OQ1]`) |
| Unscored article, vote removed | `Vote removed` |
| Scored, no topic matched | `👍 Saved · No topics matched` / `👎 Saved · No topics matched` (plus the pane line) `[CTX D-18]` |
| Scored, no topic matched, removed | `Vote removed` |
| Matched, but every change rounds to 0.0 with no limit | `👍 Saved · Effect under 0.1 points` / `👎 Saved · Effect under 0.1 points` / `Vote removed · Effect under 0.1 points` |

### Error states

Vote requests use their own error toast (set `meta: { inlineError: true }` on the feedback mutation so the global `error.message` toast doesn't also fire), shown with `addToast(msg, 'error')`:

| Failure | Copy (problem + next step) |
|---------|----------------------------|
| Vote save / remove failed (network, 5xx) | `Couldn't save your vote. Your previous vote is back; press u or d to try again.` |
| Narrowing rejected (400: a picked topic no longer matches) | `Couldn't narrow the vote because this article's topics changed. Open Narrow… and pick again.` |
| Article gone (404) | `This article no longer exists, so the vote wasn't saved.` |
| Learned values failed (editor) | `Couldn't load learned adjustments. Close and reopen Interests to try again.` (inline, see Layout) |

On any vote error the pressed state reverts to the server's state (the by-id article is refetched) `[RES Pattern 5]`.

## Interaction & State Contract

| Behavior | Contract |
|----------|----------|
| `u` / `d` | Vote on the selected article (toggle rule), in every view, only when its by-id article has loaded. Ignored with Cmd/Ctrl/Alt held (Cmd+D stays the browser bookmark key), and while focus is in an input (existing guard) `[CTX D-01]` `[RES Pitfall 6]` |
| `Shift+D` | Opens the picker only when the narrow control is visible; otherwise a no-op (it never casts a vote) `[CTX D-13]` `[DEFAULT]` |
| Toggle source | The pressed state and the next toggle are read from the by-id article (`['article', id]`) intent, never from a list row `[RES Pattern 5]` |
| Rapid presses | Requests are serialized; `u d u` ends as a single 👍 and each press shows its own toast in order `[REQ criterion 1]` |
| Reading pane after a vote | Badge, chips and open Why rows update from the vote response immediately (no Jev call, no extra fetch) `[REQ FDBK-02]` |
| On `/priority` | Only the voted row's badge is patched in place; other rows keep their served badges; the list never reorders; `↻ Ranking changed — refresh` lights `[CTX D-06]` |
| Other lists | Every visible badge refreshes (invalidate `['articles']` and other by-id articles); order is by date, so nothing moves `[CTX D-05]` |
| Read state | Unchanged by votes; `autoMarkReadDelay` still applies `[CTX D-04]` |
| Topic editor | Learned values refresh after each vote; an open dialog's unsaved row edits are never overwritten `[RES Pattern 4]` |
| Picker open + article change | The picker closes with no request |
| Create topic from article | Opens Interests with the draft; the vote, the article and its score are unchanged; saving the topic lights the Priority hint (existing interest-mutation behavior) and never re-judges this article `[CTX D-21]` |
