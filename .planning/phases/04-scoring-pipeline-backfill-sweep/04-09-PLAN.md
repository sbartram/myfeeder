<objective>
Close UAT gap G-04-1: make `./gradlew bootTestRun` a supported live-Jev local run without touching test isolation.

Root cause (from `.planning/debug/boottestrun-live-jev-unconfigured.md`): bootTestRun runs `TestMyfeederApplication` on the test runtime classpath, so `src/test/resources/application.yaml` shadows the main `application.yaml` (Spring Boot loads only the first `classpath:/application.yaml`). The test yaml is offline by design: it has no key placeholder, the base-url is `http://127.0.0.1:9` and `sweep-initial-delay` is `PT1H`. So an exported `MYFEEDER_TYPESAFE_API_KEY` never binds, and the HTTP timeouts and app name are lost as well.

Fix: add a dev-only profile overlay, `src/test/resources/application-dev.yaml`, and activate it only from `TestMyfeederApplication` with `.withAdditionalProfiles(DEV_PROFILE)`. With no profile, the test environment stays byte-for-byte the same. The debug session trialed this option and found it the only one that leaves the existing guards intact. The rejected options were renaming the test yaml to `application-test.yaml`, which would bind the real `.envrc` key in tests, and env overrides in `.envrc`, which would make the whole suite live. Guards keep the overlay in step with main and stop any test from activating it. The docs then describe the working procedure.

Purpose: the phase 04 live-key UAT check (and every future local live-Jev check) works with the documented procedure: export `MYFEEDER_TYPESAFE_API_KEY`, run `./gradlew bootTestRun`.
Output: overlay yaml, one-line entry-point change, `DevProfileConfigTest`, a runtime guard in `MyfeederApplicationTests`, and a surgical CLAUDE.md and 04-05 human-check update.
</objective>
