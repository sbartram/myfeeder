<objective>
Keep the Priority list still while the user triages it, let the keyboard walk the ranked order (with `j` paging past the last row), and tell the user when a refresh would change the ranking.

Purpose: PRIO-05 (D-07, D-09), PRIO-07 (`j`/`k`, `Shift+A`, D-11) and the D-08 refresh/hint model. Research Pattern 5 verified that any plain refetch of an infinite query reloads every page, so read and star changes must be patched into the cache in place, and re-ranking happens only through `resetQueries` or re-entry.

Output: `patchPriorityArticle`, `fetchNextNewId`, `usePriorityStore`, Priority-aware keyboard handling, leave-time cache removal, and the "Ranking changed" hint.
</objective>
