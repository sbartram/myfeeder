# Phase 7 Plan 04: Calibration Replay Tooling Summary

**A read-only psql replay of the app's own Priority blend. The blend SQL is reflected from `InterestScoreQueries` and pasted byte for byte, and a drift-guard test pins it. A candidate-grid driver runs it with `default_transaction_read_only=on`. On a scratch Postgres it reproduces the app's badges exactly (91 at profile-points 100, 61 at 60).**

## Accomplishments

- `scripts/interest-calibration-replay.sql` has six sections: `summary`, `top`, `bottom`, `window-summary`, `votes` and `learned`.
  - `summary` gives the tier histogram with inclusive-low boundaries like `tierOf`, the p10 to p95 percentiles, and the `at_zero`, `at_100` and `ties_at_min_raw` counts.
  - `top` and `bottom` list 20 articles each, in KEYED_ORDER's tiebreak order.
  - `window-summary` repeats the summary over all SCORED articles in the window, read or unread.
  - `votes` counts the thumbs votes.
  - `learned` shows the learned model per topic id and never a topic name.
  - Each statement repeats the verbatim blend on a single line, because a read-only session cannot create temp objects.
- `scripts/interest-calibration-replay.sh` (mode 100755) takes `PP:HIGH:NEUTRAL...` arguments.
  - Before any psql call it checks every candidate and the LEARN_RATE, LEARNED_CAP and WINDOW_DAYS values as numbers, and requires MYFEEDER_PG_PASSWORD. Either failure exits 2.
  - It exports `PGOPTIONS='-c default_transaction_read_only=on'`.
  - It writes one TSV per candidate under `$OUT_DIR` (umask 077). The default is `$HOME/.cache/myfeeder-phase07/replay`.
- `InterestCalibrationReplaySqlTest` has 6 tests and needs no Docker. The drift guard covers `blendCte(UNREAD_SCOPE)`, `blendCte(window scope)`, `LEARNED_CTE` and `INTEREST_SCORE`. The other tests cover the read-only keyword/backslash scan and the driver's input checks, run against `127.0.0.1:1`.
- `InterestScoreQueries.blendCte` is now package-private. That signature line is the only change to the file.
