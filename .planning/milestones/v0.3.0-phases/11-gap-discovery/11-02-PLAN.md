<objective>
Give the backend its two writes (GAP-02, GAP-03, GAP-05; D-13, D-17, Phase 8 D-14):
- `PUT /api/interest/suggestions/{articleId}/dismissal` writes DISMISSED: bodyless, idempotent, 204 or 404.
- `POST /api/interest/topics` accepts an appended optional `sourceArticleId` and writes TOPIC_CREATED in the same transaction as the topic insert.

Both use one idempotent store method, `INSERT ... SELECT ... ON CONFLICT DO NOTHING`. It keeps the first reason and never fails on a stale article id.

Task 1 (tracer) wires the dismissal end to end over HTTP. Task 2 threads `sourceArticleId` through the topic-create contract with unit and slice proofs. Task 3 proves atomicity and permanence over HTTP, documents the backend in CLAUDE.md and runs the full backend suite.

Purpose: the stored handled/dismissed state is the only thing that clears a suggestion, because articles are never re-judged (Phase 3 D-21).
Output: the enum, the store write, the PUT route, the appended request field, the transactional create, and their tests and docs.
</objective>
